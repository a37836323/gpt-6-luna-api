gpt-6-luna Decisions API 使用说明：三种问题类型、输入限制与中转可用性

Decisions API（POST /v1/decisions）是 OpenAI 专门做分类、路由、打分的接口，目前只支持 gpt-6-luna：10 月 6 日以 beta 发布，10 月 22 日正式可用。它不生成自由文本，而是对你提的每个问题返回带类型的答案：predicate 返回条件成立的概率，choice 从固定选项里选一个，score 按评分档位给出加权分数。需要注意的是，OpenLux 价格接口目前给 gpt-6-luna 标注的接口类型只有 openai（Chat Completions）和 openai-response（Responses），没有 Decisions；要用 Decisions 需要直连 OpenAI 官方。下面按官方 Decisions 指南、创建 decision 的接口参考和更新日志逐项说明。

Decisions API 是什么，和 gpt-6-luna 是什么关系

官方指南的定义是：Decisions API 接收文本、图片和 JSON，返回带类型的答案，典型用途是分类、请求路由和优先级排序。接口地址是 POST /v1/decisions，接口参考写明 model 只支持 gpt-6-luna，指南也称它是「目前唯一支持的模型」。官方指南还称它比 Responses API 快约 10 倍，这是官方说法，本页没有独立验证。

OpenAI 更新日志里的时间线：2026 年 10 月 6 日以 beta 形式随 gpt-6-luna 发布；10 月 15 日在 GPT-Live 里加入了原生 Decisions 集成；10 月 22 日正式可用，并加入了共享输入的提示缓存。

指南「What's new」一节列出了 beta 之后新增的能力：提示缓存、问题里可以带图片、input_json 内容块、每次请求最多 400 个问题（beta 时是 200 个）、除 base64 data URL 外还支持公网 HTTP/HTTPS 图片地址、对话历史里可以带函数调用和自定义工具调用及其输出、组织级用量报表、GPT-Live 集成和 Private Link。如果你在 beta 阶段试过并遇到「问题数超限」「图片地址不支持」，这些限制已经变了。

一次请求的三个字段和三种问题类型

请求体的核心只有三个字段：model 写 gpt-6-luna；input 是所有问题共用的证据，可以是一段字符串，也可以是按顺序排列的消息、工具调用和工具输出数组；questions 是问题列表，每个问题有 type、instructions，按类型再带 choices 或 levels。建议每个问题都给一个唯一的 name，返回时会原样带回，方便对应。

predicate 用来判断一个条件是否成立，返回 probability，是 0 到 1 之间的概率。例如官方示例问「照片里的商品是否有可见损坏」，示例返回 0.92，超过多少算「有损坏」由你自己定阈值。

choice 用来在无序类别里选一个。choices 要有 2 到 255 个不重复的选项，每项有 value（字符串或布尔值）和可选的 description；接口参考特别说明字符串和同文本的布尔值算两个不同的值。返回 choice（选中的值）、probabilities（每个选项的概率）和 confidence。官方建议加一个 other 之类的兜底选项，覆盖你的类别没想到的输入。

score 用来按有序档位打分。levels 要有 2 到 10 档，每档有 label 和可选的 description，按从低到高排列，下标从 0 开始。返回的 score 是各档下标按概率加权的平均值，同时返回每档的 probabilities 和 confidence。官方举的例子是三档概率分别为 0.1、0.7、0.2 时，score 为 1.1。

input 能放什么，不能放什么

按指南和接口参考：user 消息可以放 input_text、input_image 和 input_json；developer 和 system 消息只能放文本，system 消息按 developer 消息处理；assistant 消息放 output_text 或 refusal；函数调用和自定义工具调用的输出可以是文本或图片，并且每个工具输出都要用 call_id 对应到它的调用。

不支持的内容：文件、音频和 item 引用。图片只能用 base64 data URL 或公网 HTTP/HTTPS 地址，不支持 file_id；detail 可选 low、high、auto、original，默认 auto。

input_json 只能出现在 user 消息里，把对象或对象数组放进 data 字段。接口参考给出的上限是 32 层嵌套、10,000 个值、压缩后 256 KiB。指南说明 data 里即使有 role 这样的键也只当作数据，传 JSON 也不会改变返回格式。

问题本身也可以带图片：predicate、choice、score 的 instructions 可以是由 input_text、input_image 组成的非空数组，不需要 role 包装。官方给的用法是把一张参考图放在 input 里，每张候选图各提一个问题；问题里的图片和 input 里的图片共用同一套单次请求图片数量限制。

怎么读返回结果、怎么定阈值

返回对象里的 answers 与 questions 顺序一致，每个答案带 name 和 type。任何一个问题都可能返回 type 为 refusal 的拒答，其它问题照常返回答案，所以代码里要先判断 type 再取 probability、choice 或 score。官方各语言示例都处理了 refusal 分支。

一次请求可以问 1 到 400 个问题，类型可以混用。但如果一个判断依赖另一个判断的结果，官方建议拆成先后两次请求。写问题时尽量基于可观察的标准、一个问题只管一件事；choice 的选项之间、score 的相邻档位之间要区分清楚。

阈值怎么定，指南的建议是用你自己业务里带标注的样本来校准，同时权衡误报和漏报各自的代价，而不是直接拿 0.5 当分界线。

用量看 usage：input_tokens、output_tokens、total_tokens，以及 input_tokens_details 里的 cached_tokens 和 cache_write_tokens。官方说明后两者已经包含在 input_tokens 里，不要重复相加。组织管理员可以用带 api.usage.read 权限的管理 Key 查 GET /v1/organization/usage/decisions，其中 num_model_requests 统计的是请求数，不是问题数。价格与缓存计费以官网价格页为准。

什么时候不该用 Decisions

官方明确列了两种情况：需要模型按你自己的 JSON schema 输出对象（例如抽取字段、写解释）时，用 Responses API 的 Structured Outputs；需要模型发起带参数的工具调用时，用函数调用。

另外，Decisions 只负责回答问题，不会替你执行任何动作。比如路由场景里它告诉你这条请求该分到哪个类别，真正的转发、工单创建要由你的程序根据答案去做。

所以可以这样判断：结果只需要「是否成立的概率」「从固定类别里选一个」「在几档里打个分」，并且希望拿到概率和置信度，就适合 Decisions；结果需要自由文本、结构化字段或工具调用，就留在 Responses 或 Chat Completions。

通过 OpenLux 中转能不能调用 Decisions

OpenLux 价格接口给 gpt-6-luna 标注的接口类型目前只有 openai 和 openai-response，也就是 /v1/chat/completions 和 /v1/responses，没有标注 Decisions。本页没有核实 /v1/decisions 经中转的行为，不要按「中转支持 Decisions」来设计系统；确实需要 Decisions 的概率与置信度输出，请直连 OpenAI 官方接口。

如果只是想通过中转用 gpt-6-luna 做分类，可以走 Responses API 的 Structured Outputs：在 text.format 里设 type 为 json_schema、strict 为 true，用 enum 列出允许的类别。官方 Structured Outputs 指南用分类做过示例，并说明开启后不用担心模型输出不存在的枚举值。要注意这种写法拿到的是一个按 schema 生成的 JSON，没有 Decisions 那样的 probability、probabilities 和 confidence，二者不是同一个东西。

调用前的验证步骤：Base URL 填 https://api.openlux.ai/v1，Key 在 OpenLux 控制台「令牌」页创建；先请求 /v1/models，能列出模型说明地址和 Key 都对，返回 401 说明 Key 错或没带上；再向 /v1/responses 发一个 model 为 gpt-6-luna 的最小请求，确认能拿到回复，最后再加上 Structured Outputs 的 schema。推理档位、采样参数和工具调用的限制，见本站「参数与端点」一页。
